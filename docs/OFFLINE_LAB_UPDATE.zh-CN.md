# 实验室离线最小更新操作说明

适用版本：2026-09-10，34 个 Session，每组 18 次视频内容抽查。

## 只带一个小包，旧文件不用替换

把 `视频EEG_34组_离线最小更新包.zip` 复制到移动硬盘。包内有新版源码、34 组清单、完整题库和三个双击入口，不含视频、Python 环境或任何被试数据。实验室电脑不需要联网，也不需要运行安装器。

这是新增一个文件夹的更新方式：复用每台电脑原有的环境、视频库和设备配置，保留旧程序作为继续旧实验及回退的入口。不要用本机整个项目覆盖实验室电脑，也不要复制本机的 `.venv`、`runtime` 或 `data`。

## 每台电脑按下面做

1. 等当前实验结束并确认数据保存，再关闭程序。先将该电脑已有的 `data` 和其他实际采集输出目录复制一份到备份硬盘，不能剪切。自定义数据目录可在原 `video_eeg/config/video_config.yaml` 的 `storage.records_dir` 中查看。
2. 找到这台电脑原程序的真正目录：里面应有 `video_eeg`、原启动脚本，通常还有 `.venv`。不要解压到桌面快捷方式所在目录。
3. 解压小包，将其中整个 `_video_eeg_34_update` 文件夹放进原程序目录。不要把它内部的文件散放到旧程序中。如果出现覆盖旧文件的提示，先取消，检查放置位置。

正确位置示例：

```text
原程序目录/
  .venv/                      原环境，保留
  video_eeg/                  原代码和配置，保留
  data/                       已采数据，保留
  run_video_formal.bat         原入口，保留
  _video_eeg_34_update/        仅新增这个文件夹
    01_先检查.bat
    02_Demo.bat
    03_正式34组.bat
    video_eeg/
    scripts/
```

4. 双击新增文件夹中的 `01_先检查.bat`。看到 `OFFLINE CHECK PASSED` 才继续。检查会核对更新包、原环境依赖、7949 个正式视频的文件名和大小，以及34组抽查安排；不会连接 EEG 设备或修改旧数据。文件大小检查不等于逐字节视频校验。
5. 双击 `02_Demo.bat`，确认窗口、中文、视频、答题键及 Esc 退出正常。Demo 使用模拟 EEG。先在一台电脑试好，再给其他电脑重复以上步骤。
6. 连接这台电脑原来使用的 EEG 设备，双击 `03_正式34组.bat`。先用独立测试被试编号做设备连接和保存检查，确认实际 EEG 与行为文件写出，再开始新实验。正式入口仍使用真实 EEG；Demo 通过不能替代这一步。

## 已经开始的实验怎么处理

已按旧17组方案开始的被试，继续用原入口、原被试编号完成原方案。不要把旧 Session 编号或 `session_state.json` 搬到新34组中，也不要删除旧进度重新抽签。新34组入口用于新开始的实验；需要调整正在进行的研究安排时，先明确被试后续采用哪个方案，程序不自动迁移进度。

新版每组视频净时长约 88.35–88.94 分钟，包含五种时长分段，组内顺序随机并在续做时保持；休息和答题时间另计，没有90分钟强制截止。抽查文字为“请根据刚才的视频内容选择最符合的一项，答题不限时”。

## 数据放在哪里

- 新版正式数据和进度：`原程序目录/data/video_question_complete_runs/protocol_34sessions/`。
- 新版 Demo 采集输出：`原程序目录/data/offline_upgrade_demo/`；Demo 行为进度另在更新文件夹的 `data/demo_runs/`。
- 原数据留在原处。新版不导入旧17组进度。如果原来已使用34组且上述目录已有同名被试进度，新版会遇到原有记录；请先确认方案和题库一致，不能随意复用编号。

备份时同时备份原数据和新增输出。不要在实验进行中拔走视频所在硬盘；建议将更新文件夹放在电脑本地磁盘。

## 检查失败时

不要重装或覆盖旧环境，继续用原入口。把更新文件夹里的 `check_report.txt` 带回联网电脑分析。小包要求原环境为 Python 3.12 且具备新版运行依赖；无法预先保证未知版本的每台旧电脑都满足。若缺环境组件，需要另准备匹配的离线环境包，本包不会联网安装。

若出现 `缺失或不匹配的视频.txt`，表示该机视频库不满足新版清单。只补齐报告指出的缺失视频，来源为本机完整母库 `video_materials/formal_v1/videos`，目标为检查报告显示的“实际目录”。大小不一致的文件先备份并核对，再处理。不要把视频复制进更新文件夹，也不要覆盖原设备配置。

启动脚本查找原程序内的 `.venv/Scripts/python.exe`，其次查找原程序上一级的同一路径。其他环境布局需要根据检查结果单独适配。原视频位置从原正式配置解析；每台电脑的设备类型、地址、采样率等沿用该机配置。

## 回退

关闭新版，重新双击原来的入口即可。保留新增文件夹及所有新旧数据，不需要卸载或删除任何内容。不要移动或重命名原程序及其 Python 环境目录。

## 给维护人员

构建命令：`python scripts/build_offline_lab_update.py <新的输出目录>`。包中 `OFFLINE_FILES.json` 记录文件哈希，运行前自动检查。不能只替换一个 runner 文件：新版流程依赖配套题库、Session 清单和其他模块；此小包把这些依赖一起带齐，避免手工逐项覆盖。

本机模拟旧目录的验证结果见 `docs/OFFLINE_UPDATE_VALIDATION.md`。实验室各台机器的真实设备采集仍须按上述步骤现场验证。
