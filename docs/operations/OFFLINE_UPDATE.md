# 硬盘部署与既有离线包

本页按版本汇总离线操作，避免把不同包的入口和数据混用。最新GitHub源码只用run_experiment.bat；已经部署的独立小包继续沿用包内入口。框架整理不直接覆盖这些在采目录。

## 只整理源码的新版本如何更新

1. 停止采集并正常保存。保留原整个程序及data；不对实验目录做镜像删除。
2. 新GitHub源码完整解压到旁边新目录；联网新电脑按README安装。离线已有健康Python3.12的电脑不要重新下载环境，可在原程序目录合并白名单源码，但不得覆盖旧配置或data，优先由维护人员使用已验证的小包。
3. 需要继续旧17组时继续原协议；仅装断流保护可用下方补丁说明，不必切换协议。新旧协议的状态不自动转换。
4. 当前硬盘V2交付包和断流补丁是独立发行物，其固定OFFLINE_FILES清单不得手工改乱；GitHub文件改名不改变已发包的操作。
5. 若用新源码启动旧被试，把原数据按原相对路径完整复制到新项目的data中（不合并同名被试、不只拷NPY），同时保留原设备和视频路径配置。统一启动器会找到旧位置。可先只读原目录核对，不删除旧副本。

[断流小补丁](EEG_AND_RECOVERY.md)只换源码，保留原协议。以下各节为对应已发包的具体操作说明，不是让所有电脑依次安装所有包。

# 利用硬盘最快更新到情绪协议 V2

适用于实验室只有v1（17个Session）的电脑。使用新增文件夹，复用原Python、设备配置和视频，不覆盖原程序或已采数据。

## 在这台电脑上带走什么

移动硬盘交付目录：`E:\video\实验室离线更新_情绪V2_20260915`。
带走整个目录，其中包括00部署BAT、部署PS1、`_video_eeg_emotion_v2_update`代码包与操作说明。

如果目标电脑还没有情绪视频，还需硬盘上保持这套现成材料：
`E:\video\video_materials\formal_v1\emotion_video\selected`，共3,138段、约9.87 GB。
不需要再次复制普通视频，不用复制parquet、下载缓存、其他电脑的data或Python环境。
硬盘换成F/G等盘符后，部署脚本按自身相对位置找材料，不要求固定E盘。

## 到实验室后的最短步骤

1. 结束正在进行的实验并正常保存；备份旧data。不要在采集中更新。
2. 双击硬盘交付目录的 `00_一键部署到实验室电脑.bat`。
3. 选择**原程序主目录**，其中有原正式配置（当前源码为 `video_eeg/config/video_legacy_17_config.yaml`）和启动BAT；不要选video_materials，也不要选新旧更新包内部。
4. 程序在旧目录内新增 `_video_eeg_emotion_v2_update`。旧环境、旧配置、旧数据不被替换。
5. 在新文件夹依次双击 `01_先检查.bat` → `02_Demo.bat` → 完成真实设备短测 → `03_正式45组.bat`。
6. 把03入口创建为清楚标注“V2 七级 喜好 抽查 疲劳”的新快捷方式。旧快捷方式供旧协议继续使用。

## 哪些视频会复制

部署器优先查找目标电脑：根目录本机 `emotion_library.local.json` 指定位置、旧目录的`emotion_video`、项目旁标准`video_materials/formal_v1/emotion_video`。
若找到3,138文件的selected目录，新增一个路径配置直接复用，**不再复制约9.87 GB**。该快速数量检查不是完整验收，01仍逐项核对SHA256和ffprobe。
若未找到，则从硬盘标准位置复制3,138个文件到新更新包的`emotion_video/selected`。复制支持中断续传，不删除旧目标、不使用镜像删除。
如果情绪库在未自动识别的其他目录，可在复制前把旧项目的本机`emotion_library.local.json`指向该emotion_video目录。

原普通视频按旧配置复用。01会核验全部11,087段材料及情绪文件校验值，耗时取决于硬盘速度；请让检查完成，不以“复制完成”代替“材料通过”。
完成检查后应可拔掉传输硬盘；若你手动把材料路径指向外接盘，则运行期间必须保持该盘连接。

## 2026-09-16 疲劳五点评分更新

上文已交付硬盘包不会随GitHub自动变化。当前源码的新Session疲劳页使用数字1–5，题干为“当前您的疲劳程度是？”，1几乎不疲劳、5非常疲劳，完全无法继续观看。需更新程序源码才会生效，不重装环境、不重新复制视频、不覆盖data或Session状态。已开始并保存二分类或七点疲劳协议的Session保持原量尺续跑，下一个新Session使用五点评分。旧记录保留原fatigued=0/1或fatigue_rating=1–7，不换算成1–5。新记录保存fatigue_rating=1–5、fatigue_scale_min/max、fatigue_measure、fatigue_wording及完整fatigue_key_map；分析时须按量尺分开。未知或不匹配的状态仍拒绝续跑，不通过改哈希强行迁移。
