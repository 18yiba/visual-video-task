# 两份源码项目之间迁移被试记录

使用 `scripts/maintenance/migrate_records.py`，先预览，再完整复制并逐文件核对 SHA256；原件保留，不覆盖或合并目标记录。脚本只需 Python 标准库，不安装依赖、不连接设备。

## 操作

先正常保存并退出两个实验程序，保留旧项目作为备份。在新项目根目录打开 PowerShell，将旧路径替换为实际路径：

```powershell
python scripts/maintenance/migrate_records.py --old "D:\旧项目" --new "D:\新项目"
python scripts/maintenance/migrate_records.py --old "D:\旧项目" --new "D:\新项目" --apply
```

`python` 可替换为本机已有 Python 的完整路径；不需要重装或同步实验环境。省略 `--new` 时，目标为脚本所在项目。

默认检查两边项目的 `data`。实际数据在外部时，加 `--source-data "D:\实际旧数据\data"` 和/或 `--target-data "D:\实际新数据\data"`。参数应指向包含 `sourcedata` 的目录，不能指向 `sourcedata` 本身。脚本不会读取安装版绑定设置，也不修改运行配置；自定义目标必须与新版实际保存位置一致。两版共享同一数据根时无需迁移，脚本会拒绝自复制。

## 自动判断边界

- 根据标准目录识别 v1/v2、旧 complete/legacy17/emotion-v2，以及 v3 的设备与视频范围；保留原目录层级和所有被试文件。状态只读检查 JSON 和层级，不改哈希、答案、快照或已完成记录，不宣称已验证协议兼容性。
- 同协议同编号多处进度、目标已有被试目录（即使内容相同）、未知状态路径、缺少状态、链接/junction、空间不足或文件变化均停止。运行期间必须保持两边程序关闭；脚本无法阻止实验程序重新启动。
- Demo、被试目录之外的 BIDS/EEGQC 导出、材料、环境和项目配置不在复制范围。保留旧项目及其配置；历史定制协议、安装版 imported 布局及任意自定义记录结构须单独核对，不自动猜测映射。
- 校验通过后逐被试提交；多个被试不是整体原子事务。失败时可能部分已提交，回执 `data/_record_migrations/<编号>/receipt.json` 列出已提交项；暂存及 `migration.lock` 保留。不要直接重跑或删除锁来绕过错误，先按回执核对。
- 完成后用原协议、设备、视频范围、编号和 Session 检查进度与保存位置；由程序校验协议兼容性。先以独立测试编号确认保存恢复，再续跑真实被试。不要在旧副本继续采集。

迁移回执包含本地被试路径和文件哈希，仅保存在私有 data 目录；不上传 Git 或源码发行包。复制校验不能恢复原来已缺失的记录，也不代表真实硬件验收。
